# awg-3xui-installer

Автономный установщик и менеджер VPN-сервера на **Ubuntu 24.04 LTS**: один скрипт ставит **AmneziaWG с нативным модулем ядра** (не userspace-Go, полный профиль обфускации **3.1**), **WireGuard tools** и панель **3x-ui**, поднимает рабочий туннель и печатает все креды. Установка через `curl | bash` идёт без интерактивных вопросов; запуск в терминале открывает меню управления (установка, удаление, переустановка, миграция на 3.1, клиенты, бэкапы, обновление).

## Что ставится

| Компонент | Источник | Тип |
|---|---|---|
| `amneziawg` (модуль ядра `amneziawg.ko`) | `ppa:amnezia/ppa`, пакет `amneziawg-dkms` | DKMS, нативно в ядре, пересобирается при обновлении ядра |
| `awg` / `awg-quick` | `ppa:amnezia/ppa`, пакет `amneziawg-tools` | userspace-инструменты AmneziaWG |
| `wg` / `wg-quick` | репозитории Ubuntu, `wireguard-tools` | модуль `wireguard` уже встроен в ядро Ubuntu |
| 3x-ui | официальный `install.sh` из `MHSanaei/3x-ui` | systemd-сервис `x-ui`, SQLite |

## Требования

- чистая **Ubuntu 24.04 LTS** (x86_64 или aarch64), VPS/сервер с systemd — **не контейнер** (LXC/OpenVZ/Docker отсекаются предпроверкой: DKMS требует собственного ядра);
- запуск от **root** через **bash** (запуск через `sh` отклоняется с подсказкой);
- **не менее 1.5 ГБ** свободного места на `/` (DKMS-сборка + 3x-ui);
- **Secure Boot выключен** (DKMS-модуль не подписан; установщик читает EFI-переменную напрямую и останавливается с понятной ошибкой);
- доступ к `github.com` / `raw.githubusercontent.com` и `ppa.launchpadcontent.net` (оба проверяются до установки);
- заголовки текущего ядра доступны в репозиториях (`linux-headers-$(uname -r)` ставятся автоматически, наличие проверяется).

## Установка (одна команда)

```bash
curl -fsSL https://raw.githubusercontent.com/aligorov/awg-3xui-installer/main/install.sh | sudo bash
```

Последовательность внутри скрипта:

1. предпроверка (root, bash, Ubuntu 24.04, архитектура, systemd, не контейнер, Secure Boot, место на диске, сеть до GitHub и PPA, защита от параллельного запуска);
2. зависимости + заголовки ядра + `fail2ban`/`nftables` (для IP Limit в 3x-ui); скрипт ждёт освобождения dpkg-лока, если его держит `unattended-upgrades` (до 5 минут);
3. `ppa:amnezia/ppa` → `amneziawg` (DKMS-модуль + tools), `modprobe amneziawg`, проверка `/sys/module/amneziawg`; если модуль не принимает профиль 3.1 (старые пакеты, например из focal-PPA), установщик сам обновляет их из noble-PPA (`--allow-downgrades`, чистит чужие PPA-записи) и перезагружает модуль;
4. проверка нативного `wireguard` в ядре + `wireguard-tools`;
5. генерация ключей и полного профиля **AmneziaWG 3.1** (`Jc/Jmin/Jmax`, `S1–S4`, `H1–H4`, маскирующий CPS-пакет `I1` в форме DNS-ответа, `HeaderProtectionKey` — шифрование заголовков, `ContentPaddingAddition`), конфиг `awg0`, NAT, `ip_forward`, запуск `awg-quick@awg0`, клиентский конфиг + QR; после запуска проверяются факты: адрес `10.8.1.1` на интерфейсе, UDP-порт слушается, `ip_forward=1`, NAT-правило на месте;
6. 3x-ui в неинтерактивном режиме (`XUI_NONINTERACTIVE=1`, случайные порт/логин/пароль/webBasePath, SQLite, без SSL); fail2ban уже установлен, поэтому настройка IP Limit не обращается к apt;
7. правила ufw (только если ufw уже активен), верификация сервисов, итоговый блок с кредами и QR-кодом.

Повторный запуск идемпотентен: существующие конфиги и установленные компоненты не перегенерируются; порт берётся из существующего `awg0.conf` (значение `AWG_PORT` из окружения в этом случае игнорируется с предупреждением). Частичная установка 3x-ui (есть бинарник, но нет systemd-юнита) чинится повторным прогоном официального установщика.

**Миграция 1.x → 3.1 автоматическая**: если на сервере уже есть конфиг старого профиля (без `HeaderProtectionKey`), установщик делает бэкапы `awg0.conf.bak-1x-<timestamp>` и `client1.conf.bak-1x-<timestamp>`, сохраняет прежний UDP-порт и перевыпускает ключи с полным профилем 3.1. Старые клиентские конфиги после миграции не работают — нужно раздать новый `client1.conf`/QR. Клиентам требуется приложение **Amnezia ≥ 5.0.1.5**.

## Управление: меню и команды

```bash
sudo bash install.sh              # интерактивное меню (только в терминале)
sudo bash install.sh <команда>    # то же самое одной строкой
```

| Команда | Что делает |
|---|---|
| `install` | установка с нуля / идемпотентный повтор / автомиграция 1.x → 3.1 |
| `uninstall` | полное удаление: туннель, 3x-ui **вместе с БД**, jail'ы IP Limit, пакеты `amneziawg*`, PPA, правила ufw; перед удалением обязательный бэкап в `/root/awg-3xui-backups/` |
| `reinstall` | `uninstall` + `install` начисто |
| `migrate` | явная миграция профиля 1.x → 3.1 (если уже 3.1 — сообщит) |
| `status` | профиль, порты, сервисы, `awg show`, версии DKMS/3x-ui |
| `add-client [имя]` | новый клиент: свободный IP из `10.8.1.0/24`, перенос всех параметров 3.1, конфиг + QR; peer сначала добавляется в ядро, потом в файлы |
| `remove-client <имя\|pubkey>` | удаление peer из ядра и конфига, конфигов и QR клиента |
| `list-clients` | таблица клиентов + runtime-статистика (handshake, трафик) |
| `creds` | креды из `/root/awg-3xui-credentials.txt` + QR |
| `backup` | tar.gz конфигов AWG, БД панели и кредов (x-ui кратко останавливается для консистентности SQLite и гарантированно запускается обратно) |
| `restore <file.tar.gz>` | восстановление из бэкапа; архив проверяется на посторонние пути (защита от tar-slip) |
| `update` | `apt --only-upgrade` пакетов AWG + перезагрузка модуля ядра + официальный `x-ui update` (данные сохраняются) |
| `restart` | перезапуск `awg-quick@awg0` и `x-ui` |
| `logs` | последние строки лога установки и journal сервисов |
| `help` | справка (работает без root) |

`curl … | sudo bash` (без TTY) по-прежнему означает автономную установку — меню не перехватывает pipe. Изменяющие действия защищены `flock` от параллельного запуска; `status`/`list-clients`/`creds`/`logs` работают без лока. При удалении сохраняются общие компоненты (`fail2ban`, `wireguard-tools`, `dkms`) и логи; runtime `net.ipv4.ip_forward` не сбрасывается (могли включить другие сервисы), но после перезагрузки вернётся к умолчанию — sysctl-файл установщика удаляется.

## Переопределение параметров

```bash
sudo AWG_PORT=51820 PANEL_PORT=8443 PANEL_USER=admin PANEL_PASS='StrongPass_123' PANEL_PATH=secret bash install.sh
```

`PANEL_USER`, `PANEL_PASS`, `PANEL_PATH` — только латинские буквы, цифры, `_` и `-` (пробелы, кавычки, кириллица и спецсимволы отклоняются предпроверкой). Порты — целые 1–65535.

| Переменная | По умолчанию |
|---|---|
| `AWG_PORT` | случайный свободный UDP 20000–59999 |
| `PANEL_PORT` | случайный свободный TCP 20000–59999 |
| `PANEL_USER` | случайные 10 hex-символов |
| `PANEL_PASS` | случайные 32 hex-символа |
| `PANEL_PATH` | случайные 12 hex-символов (webBasePath) |

## Результат

- панель: `http://<IP>:<PANEL_PORT>/<PANEL_PATH>` — логин/пароль печатаются в конце;
- клиентский конфиг AmneziaWG: `/etc/amnezia/amneziawg/client1.conf` (+ QR `client1.png`, QR выводится в терминал);
- все креды: `/root/awg-3xui-credentials.txt` (chmod 600, включая API-токен панели), дубль от 3x-ui: `/etc/x-ui/install-result.env`;
- логи: `/var/log/awg-3xui-install.log` и `/var/log/awg-3xui-install.debug.log` (трассировка команд, chmod 600; генерация ключей идёт с выключенной трассировкой — приватные ключи и `HeaderProtectionKey` в debug-лог не попадают);
- бэкапы: `/root/awg-3xui-backups/` (каталог 700, архивы 600).

## Безопасность

- Панель ставится **без SSL** (HTTP) — это осознанный дефолт автономной установки без домена. Безопасный доступ сразу после установки:

  ```bash
  ssh -L 8443:127.0.0.1:<PANEL_PORT> root@<IP>
  # затем в браузере: http://127.0.0.1:8443/<PANEL_PATH>
  ```

  Сертификат можно выпустить позже через меню `x-ui` (Let's Encrypt для домена или IP).
- Порты `AWG_PORT/udp` и `PANEL_PORT/tcp` должны быть открыты в security group облачного провайдера.
- Клиентский туннель — только IPv4 (`AllowedIPs = 0.0.0.0/0`), DNS `1.1.1.1`, MTU 1280, keepalive 25 с.
- Профиль 3.1: клиентам нужно приложение **Amnezia ≥ 5.0.1.5** (более старые не понимают шифрование заголовков). `HeaderProtectionKey` один на сервер и всех его клиентов — при добавлении клиента он переносится автоматически.

## Клиенты

```bash
sudo bash install.sh add-client phone     # конфиг + QR в /etc/amnezia/amneziawg/phone.conf/.png
sudo bash install.sh list-clients         # список и статистика
sudo bash install.sh remove-client phone  # удалить
```

Адреса раздаются автоматически из `10.8.1.2–254` по занятым `AllowedIPs`. Имя клиента — латинские буквы, цифры, `_`, `-` (1–32 символа); оно же используется как комментарий `# имя` в `awg0.conf` и как имя файлов.
